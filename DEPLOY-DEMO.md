Чеклист под конкретную цель: живая ссылка для откликов на Upwork в нише RAG.
Состояние на 13.10.2026.

- Репозиторий синхронизирован с `github.com/SamaelHugo/leadops-ai`, кроме одного локального коммита (см. шаг 1)

## Шаг 1. Запушить коммит `cb0816e`

Пуш не проходит: в глобальном git-конфиге висит ссылка на удалённую временную установку `gh`

```
credential.https://github.com.helper = !/tmp/agentforge-gh.JIGm7U/.../gh auth git-credential
```

Этот путь больше не существует, поэтому ломаются HTTPS-пуши во ВСЕХ репозиториях на машине, не только здесь. Два варианта.

**Вариант А, SSH (чинит навсегда).** Ключ на машине уже есть. Добавить его на https://github.com/settings/keys:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIFYqBahl9J25BmGrqj3t4QErmLPGU0bR6/rFw/eeXxsd alikhan@mac
```

Затем:

```bash
cd ~/projects/kwork-pipeline/leadops-ai && git remote set-url origin git@github.com:SamaelHugo/leadops-ai.git && git push origin main
```

**Вариант Б, убрать битый хелпер:**

```bash
git config --global --unset-all credential.https://github.com.helper && git config --global --unset-all credential.https://gist.github.com.helper
```

После этого обычный `git push` спросит логин и токен один раз и сохранит их в keychain.

## Шаг 2. База: Supabase

1. Создать проект на supabase.com
2. В SQL Editor выполнить `create extension if not exists vector;`. Миграция делает это сама первой строкой, но только если у пользователя подключения есть право создавать расширения. Выполнить вручную дешевле, чем ловить падение первого запуска
3. Взять строку подключения **transaction pooler**, порт `6543`, не `5432`. Серверлес на Vercel без пулера упрётся в лимит соединений

**Не менять `EMBEDDING_DIM`.** В миграции колонка объявлена как `VECTOR(dim=384)` литералом, а не из настроек, и путь OpenAI запрашивает у `text-embedding-3-small` ровно 384 измерения. Значения сходятся только на 384; любое другое уронит вставку чанков.

## Шаг 3. Ключ OpenAI со спенд-капом

Создать отдельный проект в OpenAI и ключ **только для демо**, выставить на проекте месячный лимит (хватит $5). Это главная защита: регистрацию мы закрыли, но лимит на ключе страхует от любого сценария, который мы не предусмотрели.

## Шаг 4. Vercel

Импортировать репозиторий, framework preset **Services**. Переменные окружения:

```
DATABASE_URL=<строка Supabase, порт 6543>
JWT_SECRET=cc5345818fa21195d4aac48521d4bbb64d5ec5daa74c30da15ca1b2ddf9515fc
SEED_DEMO_DATA=true
LLM_PROVIDER=openai
EMBEDDINGS_PROVIDER=openai
OPENAI_API_KEY=<ключ из шага 3>
ALLOW_PUBLIC_REGISTRATION=false
```

`JWT_SECRET` сгенерирован для этого демо и больше нигде не используется.

**Провайдеров выставить ДО первого деплоя.** Сид индексирует базу знаний тем провайдером, который включён в момент старта, а хеш-векторы локального режима несравнимы с векторами OpenAI. Переключение после первого запуска потребует переиндексации всех источников.

## Замер, на котором основано решение про провайдеров

`backend/tools/retrieval_eval.py` задаёт пять вопросов, намеренно не используя слова из документов, и считает, сколько раз нужный источник оказался первым.

```
EMBEDDINGS_PROVIDER=local   Top-1 = 1/5, Top-3 = 4/5
случайный выбор             Top-1 = 1/5, Top-3 = 3/5
```

По первому месту локальный режим не отличим от случайного. Вопрос про «password» уходит в документ о возвратах, потому что в нужном написано «passphrase». После деплоя тот же скрипт надо прогнать с `EMBEDDINGS_PROVIDER=openai` и получить второе число: это и есть пара «до и после», которую мы обещаем клиентам в откликах.

## Шаг 5. Проверка после деплоя

1. Зайти под демо-пользователем из сида
2. Задать вопрос **словами из документа** и убедиться, что ответ с источником
3. Задать тот же вопрос **перефразированно, другими словами** и убедиться, что он всё равно находит нужный кусок. Это тот самый тест, который провалил бы локальный хеширующий режим, и именно его будет делать технический клиент
4. Задать вопрос, **ответа на который в документах нет**, и убедиться, что система не выдумывает
5. Проверить, что `POST /api/auth/register` отдаёт 403

Пункты 3 и 4 это и есть пруф, который мы продаём. Если они не проходят, ссылку в отклики не ставить.

## Чего в демо нет

Vercel не поднимает n8n из docker-compose. Вебхуки будут показывать неуспешные доставки, пока не указан живой инстанс n8n. Для демо это нормально: раздел Automations показывает лог ошибок и ручной retry, что само по себе демонстрирует обработку сбоев. Но не обещать клиенту работающую доставку.
